# WT32-SC01 v3.3 display

The WT32-SC01 v3.3 uses a 3.5-inch 320x480 SPI panel. The manufacturer
datasheet identifies GPIO23 as the LCD backlight control. Board-specific
ESP-IDF and Arduino configurations identify the panel as ST7796 and agree on
the LCD wiring: MOSI GPIO13, SCLK GPIO14, CS GPIO15, DC GPIO21, and reset
GPIO22. MISO is unused. The capacitive-touch bus (GPIO18/19/39) is not used by
this splash screen.

`CONFIG_ZCLAW_WT32_SC01_DISPLAY` is disabled by default. Enable it with the
board defaults file `boards/wt32-sc01.defaults`. The firmware then initializes
the ST7796 and draws a static “HOLA PAPA / ZCLAW” boot splash. On the first
chat message, the display switches to a rolling transcript showing the user
prompt and assistant reply. The font is uppercase and approximates Spanish
accents; the browser shows the original text.

## Chat from any PC (USB Web Serial)

Open `docs/wt32-sc01-webserial.html` in a recent Chrome or Edge, connect the
WT32 by USB, click **Conectar WT32**, and choose its CP210x serial port. The
page talks directly to the board at 115200 baud using Web Serial; it needs no
Python relay, agent, or installation on that PC. The ESP32 still calls
DeepSeek over Wi-Fi and displays the transcript on its LCD. The page has no
network requests and does not read or store the API key.

The browser requires a secure context (`file://` or HTTPS) and a user gesture
to grant serial access. A USB device cannot silently launch a program on an
arbitrary PC; after opening the page, the user must authorize the port. This
is an operating-system/browser security requirement, not a firmware setting.
After permission is granted, the browser can reconnect to that authorized port
while the page is open (or when it is reopened). Each PC/browser profile needs
its own permission. The page does not send chat content to a server. The
touchscreen is not used for input yet.

### Optional local development relay

The Python relay remains available for development, but it is specific to a
host with Python and `pyserial`; it is not needed for the portable browser
page. Run `scripts/web-relay.sh --port 8787` and open
`http://127.0.0.1:8787`. If its Python environment lacks `pyserial`, use the
ESP-IDF Python environment directly:

```sh
/tmp/esp-idf-tools/python_env/idf5.4_py3.12_env/bin/python \
  scripts/web_relay.py --host 127.0.0.1 --port 8787 --serial-port /dev/ttyUSB0
```

After flashing firmware with the serial provision handler, provision the
DeepSeek key using Python with `pyserial` (the ESP-IDF 5.4 environment on this
PC):

```sh
/tmp/esp-idf-tools/python_env/idf5.4_py3.12_env/bin/python \
  scripts/provision_deepseek.py --port /dev/ttyUSB0
```

The same interpreter can run `scripts/web_relay.py` directly if the
`scripts/web-relay.sh` wrapper cannot find an installed `uv` or `pyserial`.
The script reads `providers.deepseek.auth.key` from
`~/.letta/lc-local-backend/providers/auth.json`, sends it over USB without
printing it, and updates only the `zclaw` provider/model/URL/API-key NVS
entries. It first probes for the matching firmware, preserving the existing
Wi-Fi credentials and other NVS data. The board restarts after a successful
update. The current firmware does not enable NVS or flash encryption, so a
physical flash dump can recover the stored key.

The ST7796 driver is pinned by `main/idf_component.yml` and
`dependencies.lock` (`espressif/esp_lcd_st7796` 1.5.0; ESP-IDF >=5.2).
